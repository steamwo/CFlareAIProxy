# Qoder 模型名称与默认路由

Qoder 上游模型列表同时包含匿名 `model_id` 和面向用户的 `display_name`。网关将两者分别用于内部请求与客户端 API，避免匿名名称泄露为公开模型名称。

## 模型发现

- 每次 Qoder 账号模型刷新都会保留该账号的发现记录。
- 同一次成功刷新还会更新 `credential_id=''` 的 Qoder 渠道级模型快照。
- 渠道级快照完全来自上游模型列表，不需要人工维护映射。
- 模型刷新失败时不会删除最近一次成功的渠道级快照。

## 对外模型目录

`/v1/models` 对 Qoder 返回 `display_name` 作为模型 `id`。匿名 `model_id` 仅保留在内部元数据中，用于构造 Qoder 上游请求。

非 Qoder 渠道继续使用原有的 `provider/model_id` 模型名称，不受此行为影响。

## 请求路由

客户端以 `display_name` 发起请求时，路由层会合并：

1. 相同公开模型名称的显式 `model_routes`；
2. Qoder 渠道级模型快照生成的默认候选。

因此，同一个公开模型名称可以同时路由到 Qoder 和其他供应商，并继续遵循现有优先级、权重和健康状态规则。

若用户已经为该公开名称配置了显式 Qoder 路由，该显式配置会覆盖 Qoder 默认候选。选中 Qoder 后，网关把公开 `display_name` 转换为渠道快照中的匿名 `model_id`，再交给 Qoder adapter 请求上游。

## 兼容性

- 旧的 `qoder/<匿名模型名>` 请求入口仍可解析，但不会出现在公开模型目录中。
- 网关密钥中已有的 `qoder/<匿名模型名>` 模型限制仍会授权对应的公开 `display_name`。
- 账号池只负责可用性、额度、并发和负载选择，不负责维护模型名称映射。
